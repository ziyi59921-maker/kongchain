# 证据链与可追溯性

## 适用场景

- 用户要求整理检查证据、建立证据清单或底稿引用；
- 需要说明结论依据、证据充分性与限制；
- 需要设计可复核的抽样/核对程序；
- 需要区分原始证据、加工结果与推断。

## 证据记录的最小字段

| 字段 | 说明 |
|---|---|
| 证据编号 | 稳定、可引用，如 EV-001 |
| 来源 | 系统/文件/访谈/外部函证；具体系统、文件名、页/字段 |
| 获取方式 | 导出、截图、查询、复制、现场观察 |
| 获取时间 | 日期时间与时区 |
| 责任/提供人 | 谁提供、谁导出、谁复核 |
| 完整性标识 | 文件哈希（SHA-256）、记录数、页码范围、版本号 |
| 关联对象 | 合同号/发票号/凭证号/供应商/期间 |
| 检查程序 | 对该证据做了什么（比对、重算、抽样） |
| 结果 | 一致/不一致/无法判断/缺失 |
| 限制 | 未取得原件、无法验真、系统权限不足等 |

## 证据链原则

1. **可追溯**：每个结论能回到具体证据编号与位置。
2. **原始优先**：优先原始导出/原件；截图、二次整理要标注加工步骤。
3. **时间与版本**：记录获取时间、版本、导出范围；避免用后续版本冒充当期证据。
4. **完整性**：记录记录数、总额、页码范围；说明是否截断、是否抽样。
5. **保管链**：证据从获取到归档的移交、存储位置、访问权限；敏感数据脱敏。
6. **可复核**：检查程序应能被另一位人员按记录重做。

## 事实、推断与建议

- **事实**：直接来自证据的可验证陈述（“发票号 X 的金额为 Y”）。
- **推断**：基于事实的分析（“金额与合同不一致，可能为价格调整”），必须写依据与不确定性。
- **建议**：下一步程序（“取得价格变更补充协议”）。

禁止把推断写成事实；禁止编造文件来源、页码、访谈对象或检查结果。

## 输出建议

- 先给证据清单表，再给程序与结果，最后给结论与限制；
- 对缺失证据明确写“未取得”，不要用“未发现异常”代替“未检查”；
- 金额/比例重算保留脚本或表达式。
