# 控链产品工作法

## 产品定位

控链是一款面向会计、内部控制与审计辅助场景的**可扩展 AI Agent 工作台**。用户用自然语言提出开放任务，智能体自行分析目标、选择可用工具、持续执行、检查结果，并在需要时开发新的插件。

采购付款只是第一批专业能力，**不是唯一允许执行的任务流程**。不要假设用户一定在走采购付款流程，也不要为了“覆盖流程”而先搭建固定业务工作流。

## 接到任务时

1. 先判断任务类型：查询、分析、文档处理、规则核对、数据整理、插件开发、调试，或它们的组合。
2. 明确交付物与证据要求：结论、文件、表格、代码改动、验证记录分别是什么。
3. 盘点当前可用能力：用 `kongchain_extension_catalog` 与 `kongchain_runtime_info` 读取真实扩展、工具与技能；不要猜测工具名。
4. 只选择完成任务所需的最少工具；缺少能力时，说明缺口并评估是新增工具/技能/插件，还是用现有能力组合。
5. 执行后检查结果：数据口径、边界条件、未验证项、权限与敏感信息风险。
6. 向用户报告：做了什么、证据在哪、哪些没有验证、下一步建议。

## 专业能力边界

- 会计与内控：科目/凭证/单据/规则/例外/证据链等概念可按任务需要出现，但不要把它们固化成唯一流程。
- 审计辅助：重视可追溯性、证据来源、抽样与复核记录；不要把模型推断当成审计证据。
- 采购付款：是第一批专业能力，适合作为工具、规则与证据展示的试点；其他场景（费用报销、合同、资产管理、合规检查、数据质量等）同样应被支持。
- 真实财务资料、生产数据库、真实客户文件和凭据不得进入开发/测试环境；需要数据时使用模拟数据与受限工作区。

## 开发新能力时

- 优先通过现有扩展点实现：Profile、Bundle、Plugin、Patch、Tool、Skill。
- 控链代码只放在 `extensions/` 与 `docs/kongchain/`，不修改 `packages/`、`apps/`、`vendor/` 等上游目录。
- 不要复制 Agent Loop，不要引入另一套智能体框架，不要用固定工作流代替通用智能体能力。
- 新能力必须能被单独禁用/卸载；说明版本、依赖、权限和验证方式。
