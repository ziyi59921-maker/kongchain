# 内部控制基础

## 适用场景

- 用户询问某业务环节的内部控制风险、控制点或改进方向；
- 需要把一条制度/流程描述映射到控制框架；
- 需要区分控制设计问题与执行问题；
- 需要解释内控、审计术语。

不适用于：直接下审计结论、认定舞弊、替代专业审计程序。

## 核心框架

内部控制通常从五个要素理解：

1. **控制环境**：治理、诚信与道德、权责分配、人力资源政策。
2. **风险评估**：目标设定、风险识别与分析、风险应对。
3. **控制活动**：授权审批、职责分离、凭证与记录、实物控制、独立复核、信息处理控制。
4. **信息与沟通**：内外部信息获取、传递、反馈与举报渠道。
5. **监督**：持续监督、独立评估、缺陷整改。

控制可按目的分为预防性控制与检查性控制；按对象分为人工控制与自动化控制；按层级分为公司层面控制与业务层面控制。

## 回答风险问题的结构

1. 说明业务目标与关键风险（不要只列控制清单）。
2. 按流程阶段列出风险点，并对应可能的控制活动。
3. 区分：
   - 控制**设计**是否合理（能否覆盖风险）；
   - 控制**运行**是否有效（是否有执行证据）；
   - 是否存在**补偿性控制**。
4. 说明异常与违规/舞弊的区别：异常只是线索，需要证据与进一步程序。
5. 给出可执行的核实建议与所需资料，不编造检查结果。

## 关键原则

- 职责分离：申请、审批、执行、记录、保管、复核尽量分离；小组织可用替代性控制，但要说清补偿逻辑。
- 授权审批：权限层级、金额阈值、超授权处理、审批留痕。
- 记录与留痕：控制执行必须可验证；口头说明不能替代证据。
- 独立复核：复核人应有能力、有权限、有记录。
- 成本效益与风险相适应：控制不是越多越好。
- 局限性：串通、管理层凌驾、人为错误、自动化控制配置错误。

## 输出约定

- 使用“风险—控制—证据—限制”的表达；
- 对不确定事项标注“需核实”；
- 不把风险清单写成固定审批流程；按用户实际业务裁剪。
