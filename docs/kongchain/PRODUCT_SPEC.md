# 控链 KongChain 产品规格

- 文档状态：第 1 批（扩展基础）正式规格
- 适用版本：KongChain 0.1.0 / DeepSeek Harness 0.2.2-alpha.2
- 维护位置：`docs/kongchain/PRODUCT_SPEC.md`

## 1. 产品定义

控链是一款面向会计、内部控制与审计辅助场景的**可扩展 AI Agent 工作台**。

用户可以自然语言提出开放任务，由智能体自行分析目标、选择可用工具、持续执行、检查结果，并在需要时开发新的插件。

它不是一套固定业务工作流，也不是只会回答问题的聊天界面；它是一个具有通用智能体能力、能够使用工具、能够创建和修改自己插件的工作台。

## 2. 目标用户与场景

| 用户 | 典型任务 |
|---|---|
| 会计 / 财务人员 | 单据与凭证整理、科目与口径核对、差异分析、底稿与说明生成 |
| 内部控制人员 | 控制点梳理、规则核对、例外识别、整改跟踪、证据链整理 |
| 审计辅助人员 | 抽样与复核、证据来源核验、文档解析、工作底稿与问题清单 |
| 控链开发者 | 新增工具、技能、插件、Bundle，调试扩展加载与权限边界 |

## 3. 核心交互原则

1. **开放任务**：用户可以用自然语言描述目标，而不是只能选择预设流程。
2. **自主规划**：智能体分析目标、拆解步骤、选择工具、持续执行，并在需要时向用户提问。
3. **结果检查**：智能体检查数据口径、边界条件、未验证项和风险，而不是只输出结论。
4. **能力可扩展**：缺少能力时，优先通过新增 Tool、Skill、Plugin、Bundle 解决。
5. **证据可追溯**：报告应给出数据来源、工具调用、文件路径和验证记录。
6. **人可接管**：高风险动作、真实数据、外部写入必须由权限策略和用户确认约束。

## 4. 专业能力边界

采购付款是控链的**第一批专业能力**，用于验证规则、证据展示、工具权限和插件结构；但它**不是唯一允许执行的任务流程**。

其他专业能力（费用报销、合同、资产管理、合规检查、数据质量、审计抽样、文档处理等）应以插件/技能/工具的方式逐步加入，而不是在核心代码里预先写死流程。

任何专业能力都必须满足：

- 可单独启用、禁用、卸载；
- 有独立清单、版本、依赖与说明；
- 不复制 Agent Loop，不引入替代智能体框架；
- 不把固定工作流当作通用智能体能力的替代品。

## 5. 工作台能力

- **会话**：持久化会话、历史、恢复与导出，使用 Harness 既有会话机制。
- **模型适配**：使用 Harness 既有模型适配层；控链不重写 provider。
- **工具系统**：通过 `ctx.tools.register` 注册工具，工具可被智能体自主选择。
- **技能系统**：通过 `SKILL.md` 提供任务方法，由 `dsh-skill-filesystem` 发现与加载。
- **插件管理**：使用 Harness Profile、Bundle、Patch、Plugin Manager；控链自有代码只放在 `extensions/`。
- **开发者模式**：在指定工作区内修改控链插件与允许修改的代码，执行构建、启动、测试与调试。

## 6. 开发者模式

开发者模式允许在指定工作区内：

- 修改 `extensions/**` 下的控链插件、技能、Bundle 与清单；
- 修改 `docs/kongchain/**` 下的产品与架构文档；
- 执行构建、启动、配置导出、Headless 验证、静态校验与测试；
- 读取上游源码与文档以确认 API，但**不修改**上游目录。

边界：

- 实际文件系统权限由 Harness sandbox / permission preset 执行，开发者模式不能绕过操作系统权限。
- 不得把真实财务资料、生产数据库、真实客户文件或真实凭据提供给开发/测试智能体。
- 需要执行模型生成的命令或代码时，先使用模拟数据与受限工作区。
- 修改上游核心必须单独评审；第 1 批不修改 Agent Loop。

## 7. 非目标

- 不在核心代码里实现采购付款固定流程；
- 不替换或复制 DeepSeek Harness 的 Agent Loop、Session、模型适配、工具注册、插件管理；
- 不重新设计官方前端；
- 不在本轮实现具体业务规则引擎或会计科目体系。

## 8. 第 1 批验收标准

- 原版 Harness 功能仍可运行；
- 控链扩展能被运行环境识别（profile 组合、插件加载日志、工具注册）；
- 新增扩展没有破坏原有 Agent Loop；
- 自有代码与上游代码可区分（`extensions/`、`docs/kongchain/` 与 `packages/` 等分离）；
- `PRODUCT_SPEC.md` 已建立；
- 实际启动并验证扩展加载结果。

## 9. 第 2 批交付：内控专业化

- 系统指令插件 `@kongchain/professional`：会计与财务基础、内控原则、采购付款、合同/发票/验收/付款资料、数据核对与异常、证据与底稿、审计术语、不确定性说明；
- 六条纪律：不编造证据、不把异常等同违规/舞弊、说明限制、精确计算交给程序、专业判断说明依据、支持内控范围外的开放任务；
- 专业技能（运行时通过 `dsh-skill-filesystem` 加载）：
  `kongchain-product`、`kongchain-developer`、`internal-control-basics`、`purchase-payment-analysis`、`accounting-document-review`、`evidence-traceability`、`working-paper-drafting`、`financial-data-analysis`；
- 品牌：Web 侧边栏显示“控链 / KongChain”，不重写前端；
- 开放任务实测：采购付款风险解释、模拟合同分析、Python 表格金额比对、与内控无关的文件整理规划；
- 详细证据见 [BATCH_2_VERIFICATION.md](BATCH_2_VERIFICATION.md)。

## 10. 第 3 批：插件自我扩展

用户可以在对话中提出新增能力，由智能体判断复用/修改/新建，读取插件规范，在 `extensions/kongchain-plugins/` 生成标准 Bundle（清单、版本、patch、工具、测试、README），实际执行测试，通过官方 `dsh plugin` 机制安装/更新到 profile，并验证工具可被调用。安装前必须通过检查并备份；失败时保留最后可用版本。第三方、未知来源或需要扩大权限的插件不得静默安装。

## 11. 第 4 批：开发者模式

开发者模式由工具层 guard 强制执行：关闭时禁止 write/edit 与修改型 shell；开启后仅允许 `extensions/`、`docs/kongchain/`，上游核心源码需额外 core 授权。提供 `/developer` UI 命令、diff、快照、回滚/恢复、测试与重启说明；不扩大操作系统权限。核心改动必须单独记录补丁并完成构建回归。

## 12. 第 5 批：内控工具生态

控链提供五个相互独立的内控工具：文档提取、财务比对、规则检查、证据包、Word/Excel 底稿。它们可以单独调用，也可以按用户任务自由组合，不构成固定工作流。文档解析优先轻量文本层；扫描件、缺失附件、无法验真事项必须明确限制。证据包/报告引用真实来源和 SHA-256；无源数据时拒绝生成结论。

## 13. 第 6 批：能力演化闭环

控链先发现现有 Skills/Tools/插件，确认缺口后才创建能力；创建过程必须真实测试、通过官方插件机制安装、核验注册并实际调用。每个能力记录名称、版本、来源、依赖、权限、测试、启用状态和历史；更新先保存可用版本，失败不替换旧版本。自动更新默认关闭，权限扩大、第三方代码、核心修改需审批。开发者模式支持快照、diff、回滚/恢复，但不扩大主机权限。

## 14. 插件自更新与维护

控链提供本地插件能力清单、版本检查、隔离候选升级、测试门禁、激活、启停、卸载和备份回滚。升级失败不替换旧版本；模块变更需要新进程/重启，不能谎称热重载。自动更新默认关闭，权限/依赖扩大与外部来源必须审批；当前不伪造在线插件市场，只支持本地自有插件生命周期。

## 15. 用户工作台

工作台复用 Harness 会话、模型调用、工具执行、附件上传、历史持久化和插件管理。主界面提供产品名称、自然语言任务输入、文件添加、常用任务和历史/能力/开发者入口。状态来自真实输入与会话事件；失败由原生错误卡片展示，不用动画或硬编码成功。移动端保持可用，文件能力受浏览器限制。

## 16. 财务专业能力

控链提供五类可复用财务工具：Excel/CSV 数据画像、凭证与附件核对、财务分析、审计内控底稿、财务文档交付。工具可独立调用；重要数字由 Decimal 计算并可复算；输出另存不覆盖原始文件；扫描件低置信只列待核实；无政策依据的结论不编造。

## 17. 财务专家调度

控链复用 Harness 子代理与 Agent Preset 提供六类财务专家。主 Agent 自主判断直接执行、单专家、并行或独立复核；简单任务不拆分，复杂任务只调度有独立价值的专家。交接结构包含结论、证据、计算口径、未知事项、下一步与分歧。失败与分歧必须显示，未调用专家不得显示为协作。

## 18. 任务记录与证据追溯

任务记录引用现有会话与工具事件，不另建会话数据库。每项任务记录目标、输入文件哈希、工具/专家步骤、规则与计算口径、证据、输出哈希、审批与状态。财务发现必须关联来源/方法/可复算结果/解释/未知；失败与缺失证据禁止标记完整成功。日志脱敏但不宣称防篡改或法定审计效力。

## 19. 能力演化闭环

控链先发现能力缺口，再创建、测试、安装、注册、调用新能力；更新前保存可恢复版本，失败不替换旧版本。开发者模式可改自有代码、测试、查看 diff、快照回滚恢复，但不扩大主机权限。全过程写入任务记录，区分自动化、审批和手动事项。
